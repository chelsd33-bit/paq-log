# NOL 티켓 예매 보조 (MVP)

공연 예매 과정을 **단계별로 확인하며 보조**하고, **주문 요약(결제 직전) 페이지에서 반드시 자동 실행을 멈추는** Windows용 데스크톱 프로그램입니다.

- Python 3.11+ · Playwright · Tkinter · SQLite · logging
- 대기열, CAPTCHA, 봇 탐지, 접근/구매 제한을 **우회하는 기능은 없습니다.** 이런 화면이 나타나면 "사용자 조치 필요" 상태로 전환하고, 사용자가 직접 처리할 때까지 기다립니다.
- 결제·주문 버튼을 누르는 코드 경로가 없고, 추가로 `결제/주문하기/구매하기/checkout/pay…` 문구의 요소는 클릭 자체가 차단됩니다.

> **현재 상태 — 실사이트(nol.yanolja.com) 구조는 검증되지 않았습니다.**
> 개발 환경에서 대상 사이트에 접속할 수 없어 실제 DOM을 확인하지 못했습니다. 요청대로 존재를 확인하지 못한 선택자는 만들어 넣지 않았으므로, `profiles/nol_live.json`의 선택자는 모두 `null`(미확인)입니다.
> 이 상태로 실사용 모드를 실행하면 프로그램은 **공연 페이지를 연 뒤 자동 진행 없이 안전 중단**하고, 이후 과정은 브라우저에서 직접 진행하게 됩니다.
> 전체 흐름은 **테스트 모드(로컬 모의 사이트)** 에서 동작과 테스트가 끝난 상태입니다.

## 2. 설치 (Windows)

```powershell
# Python 3.11 이상 설치 후 (python.org 설치본에는 Tkinter 가 포함됨)
cd nol-ticket-assistant
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium
```

macOS/Linux 도 동일하며, Linux 는 `python3-tk` 패키지가 필요할 수 있습니다.
이미 설치된 Chromium 을 쓰려면 환경 변수 `NOLASSIST_CHROMIUM_PATH` 에 실행 파일 경로를 지정합니다.

## 3. 실행

```powershell
python main.py
```

### 화면 구성
| 영역 | 내용 |
|---|---|
| 모드 | 테스트 모드 전환, 모의 시나리오 선택, (테스트 전용) 브라우저 숨김 |
| 공연 | 공연 URL, 공연명 검증 문구, 희망 날짜, 회차 값, 예매 시작 시간, 확인된 공연명 표시 |
| 좌석 조건 | 등급 우선순위, 매수(1~4), 최대 열 번호, 연석만, 앞 열 우선 |
| 예매자 정보 | 선택 입력. **DB·로그·설정 어디에도 저장하지 않음** |
| 버튼 | 시작 / 긴급 중지 / 브라우저 닫기 |
| 오른쪽 | 현재 단계, 단계 진행 표시, 사용자 안내, 주문 요약(공연·날짜·회차·좌석·금액), 진행/오류 로그 |

### 단계
`대기 → (시작 시간 대기) → 1 페이지 준비 → 2 날짜/회차 → 3 좌석 → 4 예매 정보 → 5 결제 전 중단`
그 밖에 `사용자 조치 필요`(대기열·CAPTCHA·직접 조작 대기), `긴급 중지됨`, `안전 중단`, `오류로 종료`.
상태 머신은 정해진 순서의 전이만 허용하므로 단계를 건너뛸 수 없습니다.

### 동작 원칙
- 각 단계는 프로필의 `identify` 선택자로 **페이지가 확인된 경우에만** 진행합니다.
- 클릭은 좌표가 아닌 **DOM 요소 기준**이며, 대상 요소는 **정확히 1개**여야 합니다(0개/여러 개면 구조 변경으로 보고 중단).
- 날짜·회차·좌석은 선택 후 **선택 결과를 다시 읽어 확인**한 다음 넘어갑니다.
- 필요한 선택자가 프로필에 없으면 추측하지 않고 중단합니다.
- 프로필이 자동 클릭/좌석 선택/입력을 허용하지 않으면(또는 `verified: false`이면) 해당 조작은 사용자에게 넘기고, 추천 좌석은 주황 테두리로 **표시만** 합니다.
- 네트워크·로딩 오류는 제한 횟수(기본 3회, 점증 대기)만 재시도합니다.
- 세션 만료 화면이 보이면 안전 중단합니다(자동 재로그인 없음).
- 로그인은 사용자가 브라우저에서 직접 합니다. 실사용 모드 로그인 세션은 `%APPDATA%\NolAssist\browser-profile` 에만 남고, 코드/DB 에 계정·결제 정보는 저장하지 않습니다.
- 긴급 중지는 모든 클릭·입력·대기 직전에 확인되며(최대 약 0.25초 지연), 이후 입력은 하지 않습니다. 브라우저는 열어 두어 사용자가 상태를 볼 수 있습니다.
- 주문 요약 페이지에서는 **읽기만** 하고 멈춥니다. 브라우저는 열린 채로 남아 사용자가 직접 확인 후 결제합니다.

### 데이터 위치
- Windows: `%APPDATA%\NolAssist\` (그 외 OS: `~/.nolassist/`)
  - `nolassist.db` — 실행 이력(`runs`), 단계 이벤트(`events`), 마지막 입력 설정(`settings`, 개인정보 제외)
  - `logs/nolassist.log` — 순환 로그 (이메일·휴대전화·주민번호·카드번호 패턴과 입력한 예매자 정보는 `[REDACTED]`)

## 4. 테스트 모드

테스트 모드를 켜면 `mock_site/` 가 `127.0.0.1` 의 임의 포트로 서비스되고, URL 이 자동으로 채워집니다. 실제 사이트에는 접속하지 않습니다.

| 시나리오 | 내용 | 기대 결과 |
|---|---|---|
| `normal` | 정상 흐름 (예매하기 → 팝업 창) | `5 결제 전 중단`, 주문 요약 표시, 결제 버튼 미클릭 |
| `soldout` | 매진 표시 | `안전 중단` (매진) |
| `noseats` | 선택 가능한 좌석 없음 | `안전 중단` (좌석 없음) |
| `expired` | 세션 만료 화면 | `안전 중단` (세션 만료) |
| `queue` | 대기열 오버레이 1.5초 | `사용자 조치 필요` → 해제 후 계속 진행 |
| `changed` | 좌석 속성 구조 변경 | `안전 중단` (좌석 상태 불명확) |

모의 사이트 기본값: 날짜 `2026-11-15`(또는 `2026-11-16`), 회차 `1`/`2`, `2026-11-14`는 매진(선택 불가), 등급 `VIP`(1~2열)/`R`(3~5열)/`S`(6~8열).

### 자동 테스트

```powershell
pip install -r requirements.txt
python -m pytest -q
```

33개 테스트가 다음을 검증합니다.
- 상태 머신: 순서 강제, 단계 건너뛰기 거부, 사용자 조치 후 복귀, 종료 후 전이 금지
- 좌석 선정: 등급 우선순위, 연석, 앞/뒤 열, 최대 열, 해석 불가 좌석
- 개인정보: 로그·DB 마스킹, `to_safe_dict`/`repr` 에서 예매자 정보 제외
- 프로필: 실사이트 프로필이 미검증이며 추측 선택자가 없음, 미검증 프로필은 자동 권한 없음
- 통합(모의 사이트): 정상 흐름이 주문 요약에서 정지 · **모의 결제 플래그가 설정되지 않음** · 결제 문구 클릭 차단 · 페이지 이동 실패(재시도 후 중단) · 공연명 불일치 · 매진/선택 불가 날짜 · 좌석 없음 · 조건 불일치 · 세션 만료 · 대기열 위임 · 구조 변경 · 시작 대기 중/진행 중 긴급 중지 · 자동 클릭 비허용 시 사용자 위임 · 미검증 실사이트 프로필의 안전 중단 · 모드/프로필 불일치 거부

### 수동 테스트 절차
1. `python main.py` → 테스트 모드 ON, 시나리오 `normal`, 시작.
2. 브라우저에서 날짜·회차 선택 → 팝업 좌석 → 예매자 → 주문 확인까지 진행되는지, GUI 단계 표시가 따라오는지 확인.
3. 주문 확인 화면에서 멈추고 GUI 에 공연명·날짜·회차·좌석·금액이 표시되는지, "결제하기"가 눌리지 않았는지 확인.
4. 시나리오별로 반복해 위 표의 기대 결과 확인.
5. `예매 시작 시간`을 1분 뒤로 넣고 시작 → 대기 중 **긴급 중지** → 즉시 `긴급 중지됨` 확인.
6. 진행 중 긴급 중지 → 이후 클릭/입력이 없는지 확인.
7. `%APPDATA%\NolAssist\logs\nolassist.log` 와 DB 에 입력한 이름·전화·이메일이 없는지 확인.

## 5. 실사이트 프로필 작성 (사용 전 필수 확인)

1. **이용약관과 자동화 정책을 먼저 확인하세요.** 자동화 도구 사용이 허용되지 않으면 실사용 모드를 사용하지 마세요. 국내에서는 매크로로 구매한 입장권의 부정판매를 금지하는 법 규정도 있으므로 관련 법령도 함께 확인하세요.
2. 브라우저 개발자 도구로 각 단계 페이지의 실제 요소를 확인하고 `profiles/nol_live.json` 의 해당 항목에 **확인한 선택자만** 채웁니다. 확인하지 못한 항목은 `null` 로 둡니다(그 단계는 사용자가 직접 진행).
3. 프로필 키 의미:
   - `show.identify` 공연 상세 페이지임을 식별하는 요소, `show.title` 공연명 요소
   - `show.date_items` / `date_attr` 날짜 항목과 값을 담은 속성(없으면 텍스트 비교), `show.selected_date` 선택된 날짜
   - `show.round_items` / `round_attr` / `selected_round` 회차도 동일
   - `show.next_button` 예매 진행 버튼
   - `seat.identify`, `available_seats`, `selected_seats`, `soldout_marker`, `seat_attrs`(좌석 ID·등급·열·번호 속성), `next_button`
   - `booker.identify`, `booker.fields.{name,phone,email}`, `booker.next_button`
   - `summary.identify`, `summary.{title,date,round,seats,price}`
   - `session_expired.identify`, `blockers`(대기열·접근 제한 화면 식별자 — 감지만 하고 우회하지 않음)
4. 선택자를 모두 확인했다면 `verified: true` 로 바꿉니다. `allow_auto_click` / `allow_auto_seat_select` / `allow_auto_fill` 은 **사이트가 허용하는 범위에서만** 켜세요. 기본값(false)이면 프로그램은 확인·추천·표시만 하고 조작은 사용자가 합니다.
5. 실제 결제가 일어나지 않는 상황(예: 판매 오픈 전 공연, 결제 직전까지만 진행)에서 단계별로 검증하세요.

## 6. 알려진 제한 사항

- **실사이트 구조 미검증**: 위 설명대로 `nol_live.json` 이 비어 있어 실사용 모드는 페이지 열기 이후 자동 진행하지 않습니다.
- **iframe/canvas 좌석 맵**: 좌석 맵이 iframe 안에 있거나 canvas 로 그려지면 현재 엔진은 좌석 요소를 읽을 수 없어 안전 중단합니다(iframe 지원은 프레임 선택자 확인 후 추가 필요).
- **팝업 처리**: 가장 최근에 열린 창을 현재 페이지로 간주합니다. 여러 창이 동시에 열리는 사이트 구조에서는 추가 검증이 필요합니다.
- **CAPTCHA 감지**: 사이트별 선택자가 없으면 reCAPTCHA/hCaptcha/Turnstile iframe 만 일반적으로 감지합니다. 감지되면 사용자에게 넘길 뿐 풀지 않습니다.
- **시작 시간**: 로컬 PC 시계 기준입니다. 서버 시간과 차이가 있을 수 있으며, 시작 시점에 페이지를 한 번 여는 것 외에 반복 새로고침은 하지 않습니다.
- **좌석 선택 시간 제한**: 사용자 직접 조작 대기 기본 10분, 대기열/CAPTCHA 대기 기본 30분 후 안전 중단합니다(`engine.Timeouts`).
- **로그인**: 자동 로그인은 지원하지 않습니다. 실사용 모드 첫 실행 시 열린 브라우저에서 직접 로그인하세요.
- Windows 실기기에서의 GUI 동작은 코드상 지원하나, 개발 중 검증은 Linux(Xvfb) 에서 수행했습니다.
